A14 — Independent backups and restoration

Design before implementation; accepted test evidence will be generated only after a fix is in place.

Components

biz_tenants

Requirement coverage

EV-01-4, EV-06-2, EV-09-1

Expected application exhibit

Backup job history, independent storage location and approved restore-test summary.

Verification and negative cases

Restore DB plus all files into isolated staging with outbound jobs disabled. Reconcile counts/checksums, recover encrypted content, measure agreed RPO/RTO and test failed-job alerting.

Artifacts after implementation

A14-backup-policy.pdf; redacted job/storage metadata; A14-restore-reconciliation.csv; timed restore-report.pdf; alert results and operator/reviewer approvals.

Review and ongoing operation

Infrastructure and custodian witness recovery; confirm independent storage and lawful retention. Run scheduled restore exercises and after material architecture/key changes. Job success alone does not prove recoverability.

History and migration

Do not invent legacy consent times, rewrite existing clinical seals, or record mock authority responses as real acceptance.

Deployment

carejiox, carejiox_template, hhh — demo environments

Dependencies and claim limits

Technical acceptance does not replace policy approval, government decisions or clinic obligations.

Implemented control scope

Existing database-plus-filestore backups use streamed authenticated encryption, external key and artifact digests. Restore validates both artifacts and rejects unsafe archive members. Restored cron/mail COPY rows are neutralised before atomic schema publication. Registered legacy pairs are migrated explicitly.

Remaining acceptance and external work

Independent/off-host storage, independent key escrow, agreed RPO/RTO, backup retention and periodic witnessed restore schedules remain operational tasks.
