A08 — Lawful signing and verification

Design before implementation; accepted test evidence will be generated only after a fix is in place.

Components

health_emr, health_compliance

Requirement coverage

EV-08-1, EV-08-2, EV-08-3

Expected application exhibit

Signed clinical document and visible verification result; an altered copy fails verification.

Verification and negative cases

For the selected lawful method, test signer attribution and confirmation. Where CA signing applies, verify outside the app, preserve signed bytes and signing-time certificate/status evidence, and test tampering/revocation handling.

Artifacts after implementation

A08-signed-synthetic-sample.pdf; detached signature/container if used; certificate-chain-and-status evidence; independent-verification.pdf; provider/method assessment.

Review and ongoing operation

Legal/clinical owner selects the lawful method by document. No personal signing key enters the pack. Refresh on provider, signing component, standards or method changes; retain long-term verification material.

History and migration

Do not invent legacy consent times, rewrite existing clinical seals, or record mock authority responses as real acceptance.

Deployment

carejiox, carejiox_template, hhh — demo environments

Dependencies and claim limits

Authority specifications/onboarding and provider credentials have not been arranged; no live submission or CA certification claim.

Implemented control scope

Internal clinician confirmation identifies the authenticated signer and preserves the content seal. Consent evidence PDF distinguishes drawn signatures from certified digital signatures. Integration readiness stores provider/specification/onboarding references.

Remaining acceptance and external work

Select accredited CA/equivalent lawful mechanism, obtain approved signing profile, implement its driver and validate certificates/timestamps/revocation before a certified-signing claim.
