A07 — Data-subject request handling

Design before implementation; accepted test evidence will be generated only after a fix is in place.

Components

health_compliance

Requirement coverage

EV-06-4, EV-07-4

Expected application exhibit

Case timeline, verified authority, due date, extension/refusal basis and completion evidence.

Verification and negative cases

Run request-specific access/deletion/withdrawal cases with reproducible clocks, processor handoffs, justified extensions and statutory-retention refusal. Use an integrated controlled case tool if suitable.

Artifacts after implementation

A07-request-timeline.csv; redacted case-exhibit.pdf; A07-timer-tests.json; identity/refusal/extension procedures and notification records.

Review and ongoing operation

DPO signs the applicable response rules and case outcome. Refresh when rules or workflows change and sample real closed cases periodically; simulated tests do not show all real requests met deadlines.

History and migration

Do not invent legacy consent times, rewrite existing clinical seals, or record mock authority responses as real acceptance.

Deployment

carejiox, carejiox_template, hhh — demo environments

Dependencies and claim limits

Technical acceptance does not replace policy approval, government decisions or clinic obligations.

Implemented control scope

Rights cases calculate Article 5 acknowledgement/completion clocks, distinguish processor involvement, enforce one justified extension with actual notice proof, and preserve acknowledgement/outcome proof. Company-scoped holiday calendar supports working-day deadlines.

Remaining acceptance and external work

Publish request procedures, verify identity, configure Vietnamese holidays, communicate outcomes and review legal exceptions. Workflow actions record actual communications; they do not send them.
