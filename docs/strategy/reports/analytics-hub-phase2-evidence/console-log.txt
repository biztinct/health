Pre-existing vs new
-------------------
* `[issue] A form field element should have an id or name attribute` is a
  Chrome accessibility advisory and is **pre-existing**: it is already
  present on the CMS shell BEFORE Analytics is opened. Measured directly
  rather than assumed — with the wizard open on the hub:

      document.querySelectorAll('input,select,textarea')
        .filter(e => !e.id && !e.name)
      -> {"total": 1, "inWizard": 0, "sample": ["SELECT.cms-catchment-select"]}

  The single offender is the CMS shell's catchment picker. **The wizard
  contributes none** — every input, select, textarea and radio it renders
  carries both `id` and `name`.

  On the Explore screen the same query returns 4, all of them somebody
  else's:

      ["SELECT.cms-catchment-select",      (CMS shell)
       "SELECT.bi-select",                 (biz_bi Explore dataset picker)
       "INPUT.bi-input bi-chart-name",     (biz_bi Explore)
       "INPUT.bi-input bi-field-search"]   (biz_bi Explore)

* `[debug] web_debranding: field_upgrade.js loaded` and
  `[log] Zalo Bus Service initialized` are pre-existing boot messages from
  `biz_debranding` and `health_zalo`; they appear on any full page load and
  have nothing to do with this phase.
